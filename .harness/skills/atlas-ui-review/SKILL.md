# Skill: atlas-ui-review

Для задач, когда пользователь показывает скриншот, живой интерфейс или просит улучшить UX Processing Center / Atlas Studio.

## Workflow

1. Сначала понять пользовательскую задачу экрана (что пользователь хочет сделать и что мешает).
2. Посмотреть существующий интерфейс и код (`js/features/inbox/view.js`, `styles.css`, связанные модули).
3. Классифицировать замечание:
   - bug (не работает / ломается);
   - usability problem (трудно выполнить действие);
   - visual hierarchy problem (главное не читается);
   - accessibility problem (цвет/контраст/клавиатура);
   - pure taste preference (личный вкус).
4. Приоритет отдавать первым четырём; taste-пожелания — минимально и аккуратно.
5. Улучшать локально (CSS/markup fix), не переделывать весь Atlas.

## Что проверять

- active vs compact vs final states (одна активная запись, явный фокус; разобранные/отброшенные не выглядят как формы)
- иерархия действий: primary / secondary / tertiary / destructive (Удалить не должен быть самым заметным)
- читаемость, spacing, contrast, discoverability
- date/time controls: подписи Дата/Время, контраст native picker, кликабельная область
- семантика приоритетов: цвет + текстовая подпись; цвет не должен быть единственным носителем смысла
- empty states, batch mode, search mode
- responsive behavior
- дублирующиеся контролы и действия

## Правила

- Не менять Core/data model ради визуальной правки без реальной причины.
- Не обкладывать CSS автоматическими тестами без пользы.
- Реальный browser/visual smoke предпочтительнее десятка искусственных CSS assertions.
- Если правка требует серьёзной переделки архитектуры — описать остаток и остановиться, не уходить в redesign.
