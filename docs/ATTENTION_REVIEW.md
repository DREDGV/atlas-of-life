# Обзор изменений и распределения внимания

Третья одобренная итерация карты, `0.13.0-alpha.7`.

## Пользовательский цикл

Карта → «Обзор изменений и внимания» → период 7/30 дней → причина для внимания
или историческое событие → объект на карте и Inspector → решение/действие →
сохранение → reload → обновлённый обзор.

Слева в обзоре показаны текущие просрочки, включая задачи без сферы, наступившие обзоры сфер и пауз,
активные проекты без выбранного шага. Справа показаны записанные завершения,
возвраты и обзоры по сферам. Внизу находится история с контекстом события.
Период применяется к фактам истории. Текущие обязательства видны при любом периоде.

Сфера получает намерение до 500 символов и ритм обзора 7/14/30/90 дней либо
«По необходимости». Отметка обзора сохраняется отдельным явным действием.
Она переносит дату следующего обзора. Сохранение ритма само по себе обзором
не считается. Сфера без задач участвует в этом цикле.

## Данные и границы наблюдения

- Schema 13 добавляет `reviewHistory = { since, events }`. Миграция начинает
  наблюдение в момент обновления. Старый operation log не восстанавливает историю.
- Факты записываются при Core operations, атомарно с сущностью, operation log
  и намерением доставки Sync. Ошибка storage откатывает все эти изменения.
- Записываются переходы Task в done и обратно, создание Domain/Project,
  `project.review`, `domain.review`. Редактирование текста не создаёт завершение.
- Снимок события содержит короткие названия, исходную сферу/проект, решение,
  выбранный шаг. Перенос или удаление объекта сохраняет прошлый контекст.
  Исторические сферы и факты без контекста остаются в распределении.
- До 90 дней и 2000 компактных событий. Очередная операция удаляет более старое.
  Усечение по количеству двигает границу непрерывного наблюдения.
- UI явно сообщает неполноту выбранного периода. Импорт и восстановление
  сохраняют факты снимка, но начинают новый интервал непрерывного наблюдения.
  Восстановление старого снимка может пропустить события между снимком и импортом.
- Экспорт Atlas содержит историю. Sync v1 сохраняет существующий контракт.
  История, ритм сфер и решения проектов локальны на данном устройстве Studio.

Количество завершений обозначает события. Повторное завершение возвращённой
задачи создаёт новое событие, возвраты показаны отдельно. Обзоры считаются
отдельно от работы. Количество событий не измеряет часы, усилия или благополучие.
Сравнение с предыдущим периодом и автоматическая оценка «заброшено» отложены.

## Исправленные связанные проблемы

- Загрузчик перестал назначать Task без контекста первый домен после reload.
- Переход из сводки к проекту раскрывает его страницу и фокусирует проект.
- Поля решения проекта получили однозначные доступные имена.
- У проектов устранён конкурирующий сигнал отсутствия открытых задач,
  скрывавший состояние проекта. Для пустой сферы используется точная подпись.
- Черновик намерения сохраняется при ошибке записи и смене Inspector;
  версия защищает от сохранения поверх более свежего изменения.
