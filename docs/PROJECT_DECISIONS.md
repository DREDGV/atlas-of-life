# Осмысленное состояние проекта — 0.13.0-alpha.5

Первый этап одобренного плана `superpowers/plans/2026-11-08-map-as-assistant.md`.
Дата: 2026-11-09. Реализован цикл карта → проект → решение → карта → reload.

Project хранит результат, lifecycle, причину паузы, необязательный день обзора,
дату обзора/завершения, ссылку на выбранную открытую Task. Новые поля локальны
Studio. Sync v1/C2 не превращаются в Full Project Sync.

Общая модель `js/core/project-context.js` отделяет факт завершения Task от обзора.
Переименование и перенос не являются свидетельством работы. При нехватке данных
пишем об отсутствии отмеченных завершений, не о бездействии человека.
История не реконструируется из ограниченного operationLog. Старый сигнал давности
записи остаётся буквально сигналом отсутствия изменений записи, а не работы.

Пауза видна текстом на карте. Наступление reviewOn предлагает пересмотреть её,
не возобновляет автоматически. Просрочки остаются видимыми и доступны в Today.
После завершения выбранной Task следующий шаг очищается через Core. Для завершения
проекта сначала нужно разобрать открытые задачи. Reopen Task в завершённом проекте
отклоняется: сначала верните проект в active в Inspector.

Завершённый проект остаётся обнаружимым, но его Tasks свёрнуты. Кнопка в навигаторе
раскрывает их; поисковый запрос и линзы также показывают содержимое. Позиция камеры,
раскрытие и draft — session state, в storage не попадают. При смене карточки draft
сохраняется до явного сохранения/сброса, unload предупреждает о несохранённом.

Schema 10→11 использует существующий migration backup. Новые проекты получают
поля по умолчанию; старые формы сохраняются совместимо. prepareState отвергает
неверные состояния, даты и ссылки nextActionId. Сбой записи решения откатывает
всю транзакцию; UI оставляет draft и показывает ошибку. Устаревшая форма не пишет
поверх последующего изменения проекта.
