# Карта как помощник — план реализации

**Статус:** предложение на одобрение пользователя. Реализация не начата.
**Дата:** 2026-11-08. Проверенная локальная база: `codex/map-attention`, `e978845`, 0.13.0-alpha.4, schema 10.
**Goal:** человек понимает состояние своих направлений, видит основания сигналов и принимает решение непосредственно на карте.
**Architecture:** Core хранит намерения и подтверждённые действия. Чистая модель выводит наблюдения с доказательствами; Canvas, Inspector и Today показывают согласованные данные. Предложения не меняют состояние без действия человека.
**Tech Stack:** существующие JavaScript ES modules, Canvas, DOM, localStorage, Core transactions, Node tests и Chromium smoke. Новые зависимости не требуются.
**Spec:** AGENTS.md, docs/ROADMAP_REVIVAL.md, docs/ATLAS_CORE.md и запрос пользователя в текущем диалоге: карта — умный помощник и визуализатор жизни.
**Исполнение:** последовательно по Atlas skills. Недоступные superpowers skills не являются обязательным условием. Делегирование отдельно не запрошено.

## Суть продукта и границы одобрения

Карта помогает пройти цикл: увидеть → понять причину → принять решение → действовать → увидеть изменение.
Красивое представление структуры поддерживает этот цикл. Число записей не является оценкой жизни.

Предлагается согласовать направление из трёх итераций и разрешить реализацию первой.
Вторая и третья уточняются после использования первой, не запускаются автоматически.
Предлагаемый следующий milestone — 0.13.0-alpha.5 «Осмысленное состояние проекта».
Номер подтвердить по актуальному remote перед началом; если появился новый milestone — не перезаписывать версию.
В roadmap нужно явно согласовать приоритет карты перед Smart Processing; это не объявляет весь 0.16.x завершённым.

## Правила помощника

- Факт: «Задача завершена 6 ноября». Наблюдение: «За последние 14 дней не отмечено завершений». Предложение: «Посмотреть следующий шаг». Эти уровни различаются в тексте и модели.
- Отсутствие данных показывается как неизвестность. Отсутствие задач не означает ни благополучие, ни заброшенность.
- Переименование, перенос и редактирование не считаются продвижением к результату.
- «Осмотрено» не значит «сделано». Обзор не сбрасывает сроки, давность работы и накопленные проблемы.
- Порог сигнала видим и объясним. Вместо «вы перегружены» — «4 задачи отмечены как начатые».
- Никаких автоматических переносов сроков, завершений или перепланирования.
- Первое интеллектуальное поведение работает без внешней модели. Языковой помощник возможен позже поверх тех же проверяемых фактов.
- У сферы жизни нет общего процента успешности. Доля выполненных задач подписывается буквально и не называется достижением результата проекта.

## Итерация 1 — осмотреть проект и принять решение

### Сценарий и экран

Клик по проекту → Inspector показывает желаемый результат, состояние, выбранный следующий шаг и основания сигналов → пользователь выбирает шаг, фиксирует паузу или завершает проект → карта обновляется → после reload решение сохраняется.

Панель компактная: название/результат, состояние, следующий шаг, «Почему показан сигнал», действия. Сведения о материалах и задачах остаются доступными ниже. Новая большая форма не нужна.

Состояния проекта:

- `active` — актуальный проект; отсутствие следующего шага является поводом для решения.
- `paused` — сознательная пауза; причина и необязательная дата возвращения видимы. После наступления даты появляется предложение пересмотреть паузу, статус сам не меняется.
- `completed` — пользователь подтвердил достижение/завершение результата. В общем обзоре проект свёрнут; доступен через явный показ завершённых и поиск.

Нельзя завершить проект с открытыми задачами молча. Первая версия объясняет препятствие и предлагает открыть их; массового автоматического завершения нет. Пауза не скрывает просроченные обязательства проекта из Today и сводки сроков.

### Данные и команды

Предлагаемые добавочные поля Project:

```js
{
  outcome: '',
  lifecycle: 'active', // active | paused | completed
  pauseReason: '',
  reviewOn: null, // локальная дата YYYY-MM-DD, только для паузы
  reviewedAt: null,
  completedAt: null,
  nextActionId: null // существующая незавершённая Task этого проекта
}
```

Старые проекты получают `active` без выдуманных дат обзора/прогресса. «Активен» здесь — совместимый статус, а не утверждение о недавней работе. Материалы остаются Knowledge, задачи — Tasks.

Команды в `js/core/commands.js`:

```js
setProjectOutcome(projectId, outcome, options = {})
setProjectNextAction(projectId, taskIdOrNull, options = {})
reviewProject(projectId, { lifecycle, pauseReason, reviewOn }, options = {})
```

Все используют текущую атомарную запись state + operationLog. `options.expectedUpdatedAt`, если передан, отвергает устаревший Inspector draft. Семантика возврата — `{ project, before, operation }`, как у updateProject.
Обзор пишет отдельный `project.review`, а не событие выполненной работы. Изменение результата и следующего шага журналируется отдельно. Команды не меняют due/plannedDay/focus задач.

Ссылка nextActionId валидируется: Task существует, принадлежит проекту и открыта. Завершение, удаление или перенос выбранной Task атомарно очищает ссылку; это становится видимым как необходимость выбрать новый шаг. Reopen не восстанавливает выбор самовольно.

- [ ] Добавить focused проверки переходов active/paused/completed, неизвестного проекта, некорректной даты, чужой/завершённой Task, stale draft, запрета completion с открытыми задачами.
- [ ] Реализовать команды и очистку nextActionId в существующих Task-командах, сохранив транзакционный rollback и C2.

### Задача 2. Общая модель наблюдений

**Файлы:** новый `js/features/map/project-context.js`, существующие `attention.js`, `attention-view.js`, новый `tests/project-context.mjs`.

Интерфейс:

```js
buildProjectContext(atlas, projectId, now)
// { lifecycle, outcome, nextAction, reviewedAt,
//   evidence: [{ kind, timestamp, entityId }],
//   signals: [{ kind, label, reason, taskIds }],
//   suggestedActions: [{ kind, label }] }
```

- [ ] Разделить давность изменения записи и свидетельства действий. completedAt существующих Tasks — известный факт завершения; ограниченный operationLog — дополнительное свидетельство, не полная история.
- [ ] При отсутствии свидетельств показывать «Нет данных о действиях», не вычислять фиктивную дату. Сохранить честный старый сигнал «записи не менялись», если он нужен, с буквальной подписью.
- [ ] Активный проект без nextActionId предлагает выбор шага; пауза объясняется причиной, истёкшая дата предлагает обзор. Просрочки остаются видимыми во всех состояниях.
- [ ] Проверить фиксированным now: редактирование не создаёт прогресс, review не создаёт прогресс, пауза не равна заброшенности, просрочка не исчезает, нехватка данных видима.

### Задача 3. Карта, Inspector и завершённый browser flow

**Файлы:** `js/inspector.js`, новый `js/features/map/project-review.js`, `js/features/map/scene.js`, `navigator.js`, `attention-view.js`, `styles.css`; `js/view_map.js` — только интеграция модели и видимости.

- [ ] Inspector: компактно редактировать outcome, выбирать существующий следующий шаг либо создавать Task через существующий Core flow. До сохранения изменения — session draft.
- [ ] Подтверждение обзора явно описывает результат. Сбой сохранения оставляет draft и показывает ошибку рядом с действием; success не показывается до durable commit.
- [ ] На проекте показывать текст/знак состояния вместе с объяснимым сигналом. Не вводить цветовую шкалу успешности человека. Обновить сводку без дублирования правил.
- [ ] Завершённые сворачиваются по умолчанию, но находятся поиском; переход к объекту раскрывает его. Исторические материалы проекта доступны. Пауза не исключает Task из Today.

- [ ] Проверить storage failure на форме, тёмную/светлую темы, 1440×900 и 1024×768; выполнить atlas-visual-verification и посмотреть снимки.
- [ ] Прогнать обычный Task routing, Knowledge source, перенос проекта/Undo, Today plan ≠ due, релевантные Sync проверки и baseline один раз после завершения.

### Условия приёмки итерации 1

1. Пользователь за минуту объясняет состояние проекта и выбирает действие без обхода нескольких экранов.
2. Пауза, неизвестность, отсутствие следующего шага и просрочка визуально различимы и имеют объяснение.
3. Выбор/обзор/пауза сохраняются после reload; сбой storage не создаёт ложного успеха.
4. Нет сломанных Task/Inbox/Knowledge ссылок и скрытой потери обязательств в Today.
5. Нет Full Sync новых полей: новая семантика локальна Studio; существующий Sync v1/C2 сохраняет контракт. Это указано пользователю.

После приёмки: обновить Core docs, roadmap/ledger, version module и PWA mirror; commit/push только своих файлов, Draft PR, CI точного HEAD. Не merge/deploy без команды.

## Итерация 2 — узнаваемая пространственная карта

Отдельный план после приёмки первой итерации.

- Стабильные опорные позиции сфер и проектов: добавление задачи/смена статуса не перестраивают весь атлас. Resize меняет камеру, а не смысл расположения.
- Определить единое правило сохранения позиций через Core; удалить конкуренцию auto/manual и ложное обещание drag, позиция которого теряется.
- Семантические уровни: жизнь → проекты → действия/материалы. В обзоре читаются состояния, при приближении раскрываются названия и связи.
- Визуальный приоритет определяет важность сигнала, а не число накопленных выполненных задач. Завершённое не увеличивает территорию бесконечно.
- Приёмка на 8–12 сферах, 40–60 проектах и 300+ задачах, включая длинные русские названия: не теряется ориентация, поиск раскрывает объект, клики/клавиатура доступны, нет мешающих перекрытий. Производительность измеряется на фиксированном устройстве до/после.

## Итерация 3 — обзор изменений и распределения внимания

Отдельный план, без обещания выводов по неполным данным.

- Обзор «Что изменилось»: подтверждённые завершения, решения, проекты с наступившим обзором, активные проекты без шага. Каждая строка ведёт к объекту и действию.
- Периодические направления вроде здоровья требуют своего намерения/ритма внимания; вводить его после проверки project review, а не выводить здоровье сферы из количества задач.
- Сравнение периода допускается только при достаточной истории. Существующий журнал ограничен и не заменяет durable history; определить минимальный набор фактов и правила retention отдельным решением.
- Языковой AI, если будет разрешён, объясняет и предлагает поверх этих фактов. Показывает основания, допускает отказ и не меняет данные без подтверждения.

## Осознанно вне первой итерации

AI API, календарь, native Android, Full Sync, полноценная долговременная история, автоматическая оценка сфер, глобальный редизайн и редактор произвольного графа.

## Самопроверка плана

- Пользовательский цикл замыкает задача 3; данные/сохранность покрывает задача 1; честность сигналов — задача 2.
- Единые имена lifecycle/reviewedAt/nextActionId используются во всех задачах. Review не является work evidence.
- Следующие итерации не являются обязательными зависимостями первой.
- План готов к одобрению; код продукта и версия сейчас не изменены.
