# 0.12.0-alpha.3 — Daily Reliability / Today Foundation

База: `revival-preparation` / `05796cf`, после Knowledge alpha.2.
Это укрепление текущего ежедневного сценария в 0.12.x; полный Today 2.0
остаётся этапом 0.13.x.

## Пользовательский результат

- Первый запуск открывает пустой Atlas. Ошибка чтения/JSON/формата или новая,
  неподдерживаемая схема открывает экран восстановления вместо demo fallback.
  Основное приложение и Sync до успешного восстановления не запускаются.
- Можно повторить загрузку, скачать нетронутый оригинал, восстановить
  предыдущий снимок или проверенный JSON-файл. Нормальный вход к этим действиям:
  «Ещё → Резервные данные». Восстановление требует явного действия пользователя.
- Перед обычным сохранением хранится один предыдущий snapshot. При ошибке
  записи snapshot или основного состояния команда отказывается от изменения.
- Today один: выбранные/в работе, ещё не выбранные задачи с наступившим сроком,
  выполненное сегодня. Завершение, возврат и выбор идут через Core; failure
  возвращает прежнее состояние и показывает ошибку, retry работает.

## Границы данных и восстановления

`loadState` сохраняет boolean-совместимость, а `getStorageStatus` различает
`empty`, `ready`, `error`. `storageAdapter.load` больше не превращает отказ
чтения в отсутствие данных. Валидация и миграция выполняются на отдельном
кандидате; миграционная запись должна пройти до публикации кандидата в `state`.

Ключи: `atlas_v2_data` — основной документ; `atlas_v2_previous` — один предыдущий
снимок; `atlas_v2_recovery_original` — данные до последнего явного восстановления.
`restoreAtlasSnapshot` в Core записывает `state.restore` и публикует новое
состояние только после успешной записи. Поломанный ввод, неизвестные назначения
при импорте и отказ записи не заменяют работающие данные в памяти.

Восстановление относится к этому браузеру. Оно не откатывает сервер/телефон,
не очищает credentials, cursor или существующий outbox. Локальный backup может
содержать delivery intent; его восстановление сохраняет эти IDs. Обычный JSON
export исключает локальную очередь намерений; import не воспроизводит очередь
чужого устройства. Текущие ещё не переданные намерения сохраняются.

## Надёжный переход Core → outbox

Schema 7 добавляет `pendingSyncOperations`. `runAtomicCommand` собирает все
операции до единого сохранения, включая ранее поздние `task.result.*`.
Snapshot фиксирует данные, журнал и outbound intent вместе. Затем операция
передаётся в прежний outbox. Его отказ не отменяет уже сохранённое действие
и не теряет intent; `syncNow` повторяет передачу. Outbox принимает повтор того
же ID без дублирования. После успешной передачи intent очищается; при сбое
очистки повтор остаётся безопасным благодаря существующей relay idempotency.
Нечитаемый outbox больше не перезаписывается пустой очередью.

## Today foundation

`js/features/today/model.js` содержит общие детерминированные выборки.
`status: today` означает явный выбор, `doing` — текущую работу. `due` — срок,
который сам по себе не меняет status. Quick Dock сохраняет прежнюю семантику
явной команды `!сегодня`; простое назначение due через Core не выбирает задачу.

`completedAt` принадлежит Core и нужен для списка завершённого за текущую
локальную дату; переименование завершённой задачи не делает её новой победой.
Для старых done-задач дата не выдумывается. Task status result продолжает
передаваться через C2; полноценное редактирование Task на телефоне не добавлено.

Подключённые legacy Today+ и Inspector helpers удалены из entrypoint.
Устаревший ICS exporter также отключён: он трактовал структурный due как число.
Исторические addon-файлы оставлены как неактивный код. Неиспользуемый старый
domain-menu с прямым изменением Tasks удалён. Активные Task entrypoints
используют существующие Core commands.

## Проверки и оставленные ограничения

- `tests/daily-reliability.mjs`: read denial, malformed/future data, backup/write
  failures, failed restore/migration rollback, outbox failure/corruption,
  durable C2 log/intent, Today selection vs due, completedAt/reload.
- `tools/smoke-daily-reliability.mjs`: изолированные Studio/Capture и локальный
  HTTP relay, выбор/завершение/retry/reload/phone result, повторное открытие,
  corrupt startup, скачивание оригинала и явное восстановление snapshot.
- `tools/smoke-knowledge-usability.mjs`: alpha.2 edit/move/search/reload сохраняет
  identity. Demo теперь задаётся явно только как тестовый fixture.
- Baseline включает существующие Sync C0–C4 regression tests.

Локальные snapshots разделяют квоту и судьбу browser storage: они не заменяют
внешний JSON backup и не переживут очистку профиля. Полная автоматическая починка
повреждённого Sync outbox не выполняется; оригинал сохраняется, ошибка видна.
Не добавлены dated planning, rollover, Focus-3, ёмкость дня, calendar,
универсальная история/Undo или Full Task Sync. Выбранные задачи остаются
выбранными до явного решения пользователя. Физический Android/VDS deploy
этим этапом не проверялся и не выполнялся.
