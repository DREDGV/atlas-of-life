# 0.12.0-alpha.4 — Knowledge Workspace / From Material to Action

Следующий срез Knowledge после alpha.2/alpha.3; построен поверх
`feat/daily-reliability-foundation` (`b394bb1`, Draft PR #27 на момент начала).
Не является началом Today 2.0, Map vNext или Full Sync.

## Пользовательский путь

«Материалы» в основной навигации или «Мысли и заметки» слева открывают
библиотеку в центральной области. В карточке видны тип, текстовый фрагмент,
контекст и число действий. Цвет взят из домена; тип обозначен текстом.
Поиск ищет все введённые слова в названии, тексте и контексте. Тип и домен
фильтруются независимо; доступны «Без контекста» и сортировка.

Карточка открывает существующий редактор в Inspector. «Создать задачу»
раскрывает короткую форму действия: название, домен/проект и выбор на сегодня.
Контекст материала предложен по умолчанию; для материала без контекста домен
нужно выбрать явно. Задача сохраняется в Core и остаётся доступной из материала.
В Task Inspector появилась обратная ссылка «Материал-источник».

Материал не превращается в задачу и не возвращается в Processing. Одна мысль
может дать несколько самостоятельных действий. Их перенос/завершение не
перемещает и не редактирует исходный материал.

## Данные

- `Task.sourceKnowledgeId` — необязательная ссылка на существующий материал.
  `createTaskFromKnowledge` использует общий Task command, atomic persistence,
  rollback и `task.create` log. `sourceInboxId` не копируется: исходный Inbox
  уже связан с материалом, а не с новой задачей.
- Обратный список вычисляет `materialActions`; второй persisted-массив ID
  не добавлен. Удаление задачи удаляет её из списка; завершённые остаются видны.
- Возврат материала в Inbox отказывается удалять material, если на него есть
  ссылки Tasks. Загрузка/импорт не принимают dangling `sourceKnowledgeId`.
- Schema 8 без пересоздания старых записей: migration 7→8 сохраняет данные.
  Версия отделяет новые ограничения происхождения от старых writers.
- Данные материалов и производных задач остаются локальными Studio. Полная
  синхронизация этих сущностей не добавлена; Task с `sourceKnowledgeId`
  не выдаётся за C2 Inbox→Task result.

## Редактор и отображение

Session draft текста/назначения хранится отдельно от Core и переживает
переключение карточек. Сохранение удаляет draft; «Отменить правки» возвращает
актуальную сохранённую версию. `expectedUpdatedAt` отказывает при stale save.
При незавершённых правках браузер предупреждает о закрытии/reload; draft не
является надёжным storage backup. Падение браузера может потерять несохранённое.

Рабочая область использует существующие цвета/шрифты Atlas, имеет явные
focus-состояния, компактную раскладку и светлую тему. Canvas и Today скрываются
при переходе в библиотеку. Keyboard shortcuts карты не перехватывают формы.

## Проверено

- `tests/knowledge-actions.mjs`: provenance, сохранность материала/Inbox,
  назначения, запросы библиотеки, reload, зависимый revert, удаление, failed
  persistence, stale-save refusal и отказ для dangling source.
- `tools/smoke-knowledge-workspace.mjs`: библиотека → поиск → связанная задача
  → источник → Today completion → reload; переключение draft и его отмена;
  фильтры, compact/light screenshots, отсутствие pageerror.
- Регрессии `smoke-knowledge-usability` и `smoke-daily-reliability` прошли.
- Baseline с существующими Core/Sync tests прошёл.

Следующие ограничения: нет редактируемого графа связей, архивирования материалов,
полной синхронизации задач/материалов или нового мобильного редактора. Desktop
workspace не заменяет отдельный мобильный Capture. Физический телефон и VDS
deploy не являются частью этого среза.
