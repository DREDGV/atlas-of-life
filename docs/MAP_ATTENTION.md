# Карта внимания — implementation / handoff

Начато 2026-09-22 по прямому запросу пользователя сделать карту главным
инструментом понимания состояния жизни. База: `29b239e`, ветка
`codex/map-attention`. Пять незакоммиченных файлов Today существовали до работы;
не включать их в коммит карты. Их список есть в `git status`.

## Задумка

Стабильные территории сохраняют пространственную память. Цвет территории
означает принадлежность; короткая отдельная подпись объясняет состояние.
Обзор внимания связывает сигнал с территорией и Inspector. Ни оценки жизни,
ни скрытого рейтинга продуктивности: только проверяемые факты в Atlas.

## Правила первой реализации

- Просрочки: незавершённые задачи с due до текущего местного дня.
- Много начатого: не менее 4 задач doing в одной территории. Это повод
  проверить нагрузку, не доказательство перегрузки человека.
- Без движения: открытая задача с известной датой последнего изменения
  30+ дней назад. Новая задача не маскирует старый хвост проекта.
- Нет следующего шага: ни одной открытой задачи. Материалы не считаются
  обязательствами. Пустая область может быть намеренным выбором.
- Неизвестная дата не превращается в давность; будущие даты не стареют.
- Несколько сигналов могут сосуществовать. На полотне — главный сигнал,
  в обзоре — все причины. Домен агрегирует задачи проектов и свои задачи.
- Кольцо показывает состав задач, не «процент завершения сферы жизни»;
  дуги выполненного и просроченного не перекрываются.

## Реализация

1. `js/features/map/attention.js`: чистая derived-модель, даты передаются
   явно; никаких storage, Core mutations или новых persisted полей.
2. `js/features/map/attention-view.js`: доступный DOM-обзор в левой панели,
   переключение территории → камера + существующий Inspector. Видимые
   сигналы не зависят от линзы задач; это явно подписано.
3. `js/view_map.js`: вычисление сводки при layout, использование того же
   снимка для Canvas и обзора. Текстовые сигналы вместо повторяющегося процента.
4. `styles.css`: типографика и цвета Atlas, спокойная иерархия; обе темы.
5. Focused model tests + изолированный browser smoke: переходы, обновление
   после Core-команды, reload, фильтры и скрытые домены, узкий экран.

## Критерий готовности

Общий вид различает просрочки, много начатого, старые открытые задачи и
пустые области; пользователь понимает причину и открывает нужный объект.
Обзор ничего не сохраняет и не меняет план/срок. Проверить обычные Today
и карту, обновить ledger/roadmap, commit/push только собственных файлов.

## Границы

Не вводим AI, Full Sync, историю посещений, произвольный health score,
автоматическое перепланирование, новый движок раскладки или Entity Context.
Давность изменения записи не равна реальной жизненной активности.
Переносы проектов через Core и ручная геометрия остаются отдельной работой.

## Статус

Реализовано в `0.13.0-alpha.3` (следующая alpha в текущем 0.13.x). План выше
зафиксирован до реализации. Model test `tests/map-attention.mjs` проверяет
владение задачами, план ≠ срок, неизвестные даты, независимость старого хвоста
от новой активности, снятие сигналов и отсутствие мутаций.

`tools/smoke-map-attention.mjs` проверяет в изолированном Chromium четыре
состояния, скрытый домен, сброс линзы, открытие Inspector, Core completion,
reload, обе темы и геометрическое попадание всех территорий в узкий обзор.
Скриншоты: `output/map-attention/`; до изменений:
`output/map-attention-before/`. Baseline и Today forward-plan regression прошли.

По результатам скриншотов расширен зазор территорий; упаковка учитывает
пропорции окна. Общая камера допускает 10% вместо прежних 50%, чтобы
«Всё» не обрезало данные. Canvas больше не растягивает grid за нижний край.
Панель управления переносится строками. Процент выполнения убран из подписи
территории, остаётся состав в кольце; дуги done/overdue последовательны.

Новая модель не зависит от незакоммиченного `planOrigin` другого агента.
Эти пять файлов остаются незакоммиченными и не входят в PR карты.

Итоговая визуальная проверка: 24 снимка (1440×900 / 1024×768, dark / light),
`output/map-attention-verified/current-measurements.json`. Переполнения сетки
нет, измеренные текстовые пары ≥ 4.5:1. Browser regressions map-card,
map-hit-hierarchy, map-lens прошли. Версия и PWA cache проверены capture-pwa.
Работа публикуется отдельным Draft поверх `feat/today-plan-alpha1` / PR #29;
не merge и не deploy.

## Продолжение: интерактивность и реальные связи

По следующему запросу пользователя замкнут перенос проекта. `moveProject` и
`undoProjectMove` атомарно меняют домен, пишут `project.move` / `project.move.undo`,
обновляют C2 для routed Tasks и сохраняют projectId задач/материалов. Старые
абсолютные координаты сбрасываются; Undo восстанавливает их. Undo сравнивает
полный снимок проекта, чтобы не затереть последующее редактирование, в том числе
при одинаковом timestamp. Ошибка storage откатывает всё, включая outbound intent.

Inspector получил выбор сферы, число связанных задач и материалов, квитанцию
и отмену. Drag за свободную территорию проекта переносит его вместе с орбами;
подсветка указывает домен назначения. Отпускание вне домена отменяет действие.
Перенос в тот же домен поясняет автоматическую раскладку вместо обещания
несохраняемой ручной позиции. Прямые записи project.domainId/pos и старый
частичный Undo удалены из карты. Встроенная раскладка задач остаётся автоматической.

Проверки: `tests/project-move.mjs` (rollback/outbox, связи, rawText, C2,
reload, безопасный Undo); `tools/smoke-project-move.mjs` (Inspector, реальное
перетаскивание, обе отмены, reload). Снимок: `output/map-attention/project-transfer.png`.
Это продолжение того же milestone 0.13.0-alpha.3, версия не повышалась.
