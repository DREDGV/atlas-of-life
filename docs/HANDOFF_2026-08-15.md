## 1. Направление продукта

Atlas развивается как одна система с двумя интерфейсами:

- Android Capture — быстрый захват текста и голоса на ходу, локальная работа без сети, последующая синхронизация;
- PC Studio — глубокая работа с входящими, задачами, проектами, доменами и картой жизни;
- VDS — общий надёжный слой данных и синхронизации между устройствами.

Текущий сервер синхронизирует только неизменяемые записи Inbox типа `inbox.capture`. Это ещё не единая база всего Atlas: изменения статуса, удаление, преобразование записи в задачу, задачи, проекты и домены между Android и PC пока не синхронизируются.

## 4. Почему пользователь пока не видит новую синхронизацию

Установленный APK версии 17 содержит новый диалог с коротким кодом, но на телефоне отображается старый диалог с адресом и длинным ключом. Причина подтверждена по исходникам и UI:

- service worker регистрируется и внутри Capacitor APK;
- cache name остался `atlas-capture-0.9.0-alpha.3-r3`;
- `app.js`, `setup-dialog.js`, CSS и другие модули обслуживаются cache-first;
- обновление APK не очищает старый WebView service worker/cache;
- поэтому новый APK запускает старый JavaScript.

Это главный текущий блокер тестирования: пока native cache lifecycle не исправлен, на телефоне нельзя достоверно проверить уже написанный pairing UI и последующие изменения.

## 5. Найденные проблемы, которые ещё не исправлены

### P0 — перед следующим APK

1. **Старый JavaScript после обновления APK.** Для native Capacitor service worker нужно отключить, а старые регистрации/cache удалить до импорта `app.js`. Нужен bootstrap с cache-busting, который сработает даже под старым worker.
2. **Белая область над клавиатурой.** Одновременно применяются Android `adjustResize`, Capacitor `Keyboard.resizeOnFullScreen=true` и собственный `visualViewport` handler. Вероятно, WebView уменьшается дважды. В native нужно оставить один механизм resize и задать тёмный фон WebView/окна.
3. **Ложная ошибка микрофона.** Android permission уже выдан, но клиент доверяет `navigator.permissions.query({name:'microphone'})`; после первого отказа runtime больше честно не повторяет `getUserMedia`. Нужно пробовать реальный доступ на каждом явном нажатии и показывать точный `SpeechRecognition` error.
4. **Нельзя начинать тестирование sync, пока пункты 1–3 не подтверждены на телефоне.** Иначе тестируется старый код.

### P0/P1 — сохранность и корректность данных

1. **Импорт переносит техническое состояние другого устройства.** Экспорт содержит `operationLog` и `sync.cursor`, а импорт присваивает их текущему устройству. Чужие `deviceId` сервер отвергает, а перенесённый cursor может пропустить серверные записи.
2. **Импорт не атомарен.** State заменяется до подтверждённой durable-записи. При QuotaExceeded/error возможно смешанное состояние в памяти.
3. **Повреждённый JSON не отличён от пустого Atlas.** Studio показывает demo; первая команда способна перезаписать повреждённый raw. Recovery Mode и Snapshot Store отсутствуют.
4. **Старые локальные Inbox-записи не backfill-ятся.** Миграция создаёт коллекцию, но не создаёт `inbox.capture` operations, поэтому legacy-записи могут навсегда остаться только локально.
5. **Конфликты обрабатываются неполно.** Runtime показывает conflict только для push-conflicts, игнорируя pull-conflicts. Конфликтующая pending-операция остаётся pending и может занимать первые 100 элементов очереди бесконечно.
6. **Cursor привязан только к endpoint.** Переподключение с новым credential на тот же URL не гарантирует сброс cursor. Нужен connection/dataset identity.
7. **Автоматические резервные копии SQLite и проверенный restore не настроены.** Пока VDS — единственная общая копия, это неприемлемый риск.

### P1 — продуктовая полнота

1. Синхронизируется только создание Inbox-записи; delete/status/convert/task/project/domain не синхронизируются.
2. Sync token хранится в обычном localStorage; для Android нужен secure storage/Keystore.
3. Нет QR-подключения, списка устройств, remote revoke и понятного экрана «последняя синхронизация / очередь / ошибка».
4. Online/offline handler Capture пишет в тот же status, что sync runtime, и может затереть «Синхронизировано» обратно на «Локально».
5. Многие изменения доменов и проектов в Studio всё ещё обходят Atlas Core прямыми мутациями.

### P2 — UX и сопровождение

- часть desktop controls реализована не настоящими button-элементами и хуже работает с клавиатурой/accessibility;
- мобильные sync errors слишком общие, нет журнала последней попытки;
- server health публично показывает только счётчики, но нет отдельного защищённого operational dashboard;
- документация местами описывает старые стадии Capture и требует актуализации после стабилизации.

## 6. QR-подключение: рекомендуемый вариант

Оставить восьмизначный код как обязательный fallback и добавить QR поверх уже существующего одноразового pairing protocol.

- QR содержит только версию протокола и одноразовый пяти-минутный код, не постоянный token;
- для текущего личного VDS endpoint остаётся встроенным и не принимается произвольно из QR;
- PC показывает QR и цифры одновременно;
- Android сканирует QR внутри Atlas через нативный barcode scanner;
- claim endpoint выдаёт индивидуальный device token, как сейчас;
- повторное сканирование использованного QR возвращает понятную ошибку;
- camera permission запрашивается только после кнопки «Сканировать QR».

Не следует кодировать в QR постоянный sync token или автоматически доверять произвольному endpoint: это создаёт риск отправки локальных записей на чужой сервер.

## 7. Рекомендуемая последовательность следующих работ

### Пакет A — сделать установленный Android проверяемым

1. Native bootstrap: unregister service workers, удалить только `atlas-capture-*` caches, импортировать native `app.js` с build revision.
2. Не регистрировать PWA worker на native platform; web PWA оставить рабочим.
3. Убрать двойной keyboard resize, добавить regression checks.
4. Переписать mic flow и диагностику ошибок.
5. Исправить единый статус local/offline/sync.
6. Запустить baseline/sync/android-prep, затем один новый APK и ручной smoke на Nokia.

### Пакет B — защита данных синхронизации

1. Атомарный import checkpoint/rollback.
2. Не импортировать чужой cursor и чужие pending operations как активное состояние.
3. Ввести connection identity и безопасный reset cursor при переподключении.
4. Backfill/publish flow для legacy Inbox.
5. Явно сохранять и показывать конфликты; не допускать блокировки всей очереди.
6. Добавить автоматический SQLite backup + restore drill на VDS.

### Пакет C — pairing UX

1. QR generator в Studio;
2. native QR scanner в Capture;
3. короткий код остаётся fallback;
4. список подключённых устройств и revoke;
5. secure storage токена на Android.

### Пакет D — настоящая единая модель Atlas

После стабилизации Inbox определить revisions/tombstones для mutable entities и поэтапно синхронизировать:

1. Inbox status/delete;
2. преобразование Inbox → Task;
3. Tasks;
4. Projects;
5. Domains;
6. conflict UI и audit history.

Не расширять протокол на всю модель до Recovery Mode, snapshots и устранения критических direct mutations.
