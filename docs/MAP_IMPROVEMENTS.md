# Карта Atlas — дефекты, улучшения и план

Рабочий документ по карте (`js/view_map.js`, Canvas 2D). Заведён 2026-09-12 при
подготовке к улучшениям карты. Статусы задач — в `docs/WORK_LEDGER.md`
(нумерация M-01…M-17 совпадает). Этапы версий — в `docs/ROADMAP_REVIVAL.md`
(карта = 0.16.x Map vNext + Entity Context).

**Что здесь:** что карта делает сейчас, какие дефекты подтверждены живой пробой,
что улучшать и в каком порядке, какие решения нужны от пользователя.

## Как карта устроена сейчас

- Раскладка — `layoutMap()` (`js/view_map.js:726-1091`): домен = территория-аура,
  внутри орбита детей (`project` и виртуальная группа `unassigned` = «Без проекта»),
  задачи проекта — по кольцам, задачи без проекта — спираль золотого угла и
  `separateGroup` (`:91-140`), плюс ряд-упаковка доменов по ширине (`:803-836`).
- Отрисовка — `drawMap()` (`:1093-1642`): каналы задачи — заливка = статус,
  кольцо = срок/работа, крестик = Фокус дня, дуга = давность, радиус = важность
  и оценка (`:1354-1476`); подписи — после орбов с бюджетом по соседям
  (`:1478-1540`); связи по тегам (`:1062-1090`), `dynamicEdgeCap` 300 и
  авто-деградация свечения по FPS (`:1620-1641`).
- Взаимодействие: `fitAll/fitDomain/fitProject/fitTask/fitGroup` + анимация
  камеры (`:492-690`), клавиатура по задачам с live-region (`:277-397`),
  drag&drop задач и проектов (`:1890-2208`), undo (`:2211-2231`),
  Inspector как общий «активный объект» (`:2345-2353`), `landingPing` (`:2411`).
- Сессионное состояние карты — `js/ui/map-session.js` (видимость доменов),
  остальное (`showLinks/showAging/showGlow`, `filterTag`) — в `state`, но
  сохраняется как настройки отображения.

### Ложные следы (чтобы не тратить время)

- `js/view_map.fixed.js` — легаси-файл, нигде не подключён (проверено grep:
  0 совпадений в `index.html`, `js/`, `tools/`, `tests/`), и `verify-baseline.ps1`
  исключает `*.fixed.js` из синтаксической проверки.
- `_pos` рядом с `pos` (`:894`, `:960-961`, `:1017-1018`) — старый формат,
  который больше никто не пишет.

## Подтверждённые дефекты (проба `output/map-prep-probe.mjs`, Chromium 1440×900)

### D1. Домен с одним проектом ставит проект ровно в свой центр → M-01

`const orbit = meta.children.length === 1 ? 0 : …` (`js/view_map.js:876-878`), то есть
центр слота ребёнка совпадает с центром домена. Замеры:

```text
Дом   ↔ Дача              расстояние центров  77   сумма радиусов 214   запас -137 px
Работа ↔ Запуск продукта  расстояние центров  74   сумма радиусов 204   запас -130 px
```

Проект вылезает за верхнюю дугу домена, а центр домена занимает группа
«Без проекта». У домена с двумя проектами (`children.length = 3`) проблема мягче,
но проект всё равно почти касается границы.

### D2. Вложенность территорий ломала попадание и «где я нажал» → M-04 (исправлено)

Из-за D1 все задачи проекта лежали и внутри проекта, и внутри домена; все задачи
группы «Без проекта» — внутри группы и внутри домена (11 из 11 задач пробы попадали
в две территории). `hit()` возвращал последний узел в массиве (`:1719-1735`), то
есть ответ зависел от порядка сборки узлов, а не от картинки. Исправлено: единая
функция `bestHit` выбирает **самую маленькую содержащую территорию**, а при равном
размере — нарисованную сверху (`hitRank`: задача → проект → группа → домен). Hover,
клик и drag спрашивают одно и то же, поэтому подсказка, выбор и перетаскивание не
могут разойтись. Регрессия: `tests/map-hit-hierarchy.mjs`.

### D3. Перетаскивание задачи внутри её проекта не сохраняется → M-02

Замер: координаты орба до перетаскивания и после перезагрузки одинаковые
(`272.7157…, 337.3594…`), `task.pos` остаётся `null`. Причины две:
`applyTaskPlacement` игнорирует `pos` для задачи с `projectId`
(`js/core/commands.js:339`) и `view_map.js:2119-2131` не пишет позицию для таких
задач вовсе. Пользователь видит, что орб уехал за курсором, и считает, что
«я так разложил» — на следующей перестройке раскладки орб возвращается на место.

### D4. Перетаскивание проекта пишет состояние в обход Core → M-03

`state.projects.find(...).domainId = n.id` (`js/view_map.js:2018-2020`) и
`p.pos = …; saveState()` (`:2132-2138`) — без Core-команды, без operation log,
без валидации домена. Нарушает правило «persisted data меняется только через Core
commands»; в историю и Sync такое перемещение не попадает.

### D5. В стартовом виде карта без имён → M-08

`fitAll` ограничивает масштаб 1.1 (`:544`), подписи задач требуют `scale ≥ 1.15`
(`:1482`), проектов — `≥ 0.82` (`:1326`). То есть после «Всё» видны только орбы
без названий, а имена появляются лишь по наведению.

### D6. Нет инструментов обзора → M-09…M-14

Поиска по карте нет (0 полей ввода внутри карты), линз «срок / фокус / застой /
выполнено» нет, сводки «что сегодня» нет, мини-карты и хлебных крошек нет.
Материалы домена не считаются: `state.knowledge.filter(item => n._type === 'project'
? item.projectId === n.id : (!item.projectId && item.domainId === n.id))`
(`:1255-1258`) для домена требует `!item.projectId`, поэтому материалы домена без
проекта не попадают ни в проект, ни в домен → M-05.

### D7. Карта игнорировала тему интерфейса → M-18 (исправлено)

Цвета текста и структуры в Canvas были константами тёмной темы. Замер
(`atlas-visual-verification`, светлая тема) дал контраст подписей к панели
**1.26:1** (`#cfe8ff`), **1.33:1** (`#cde1ff`), **1.95:1** (`#9dbde0`),
**1.65:1** (`#b9cbe4`), **1.38:1** (`#9ee6ff`) — то есть в светлой теме подписи
доменов, проектов, групп и бейджей практически не читались. Исправлено: палитра
карты (`MAP_PALETTE`/`mapPalette()`, `js/view_map.js`) читает тему и отдаёт цвета
текста и структуры; после исправления все пары ≥ 4.5:1. Остаток — фоновые каналы
(дуги давности, границы проектов, связи): M-18b.

### D8. Контраст вторичного текста в светлой теме → M-19 (исправлено)

`--muted: #6b7a90` давал 4.36:1 к панели и 4.02:1 к `--panel-2` — ниже порога AA
для текста обычного размера. Заменён на `#5f6f86` (5.12:1 и 4.71:1).

## Улучшения по порядку (соответствие реестру)

```text
Уровень 1 — «карта не должна врать»: M-01, M-04, M-02, M-03, M-05, M-06
Уровень 2 — «карта как инструмент»: M-08, M-09, M-10, M-11, M-12, M-13, M-14
Уровень 3 — фундамент для 0.16.x:  M-15, M-16, M-17
```

### Уровень 1

1. **M-01 Геометрия домена с одним проектом.** Не ставить ребёнка в центр: либо
   минимальная орбита, либо отдельная композиция «проект сверху, группа снизу».
   Критерий приёмки: у любого домена территории его детей не пересекаются, ребёнок
   не выходит за свою территорию, домен не «схлопывается» в один центр.
2. **M-04 Единая иерархия попадания.** Попадание и вложенность определять по
   ближайшему содержащему объекту, а не по порядку массива; слой отрисовки и слой
   попадания должны совпадать (клик по орбу — задача, клик по пустой территории
   проекта — проект).
3. **M-02 Честный drag.** Решить: сохранять позицию задачи внутри проекта (Core +
   `applyTaskPlacement`) или отключить визуальный обман и объяснить, что позицию
   задаёт раскладка. Промежуточное состояние недопустимо: сейчас карта обещает
   функцию, которой нет.
4. **M-03 Проект — через Core.** Команда перемещения проекта (валидация домена,
   operation log, undo) вместо прямых записей в состояние.
5. **M-05 Материалы домена.** Счётчик материалов у домена, включая материалы без
   проекта; решение о материалах «без контекста» — за пользователем.
6. **M-06 Двойной клик.** Оставить `dblclick` только там, где попадание
   однозначно, иначе дать альтернативу (Enter/клик по заголовку), потому что
   двойной клик по орбу сейчас ничего не делает.

### Уровень 2

7. **M-08 Имена в стартовом виде** — понизить порог или упростить приоритет
   подписей, чтобы «Всё» показывало ключевые объекты с названиями.
8. **M-09 Поиск по карте** — подсветка найденного, остальное приглушается,
   `Enter` → `fitTask` + `landingPing` (механизмы уже есть).
9. **M-10 Линзы** — «срок сегодня/просрочено», «Фокус дня», «застой 30+ дней»,
   «выполнено»; это самый короткий путь к «распределению внимания» из Map vNext.
10. **M-11 Сводка «что сегодня»** над картой (числа + переход по клику).
11. **M-12 Мини-карта и хлебные крошки** «домен → проект → задача» с возвратом.
12. **M-13 Забытые проекты и застой** — «нет активности N дней» как измеримый
    признак на территории проекта.
13. **M-14 Словарь структуры** — префиксы «ДОМЕН · / ПРОЕКТ · / БЕЗ ПРОЕКТА»
    убрать с полотна в легенду, у объекта оставить имя.

### Уровень 3

14. **M-15 Производительность** — индексы узлов вместо `nodes.find` в цикле,
    разделение статического и динамического слоёв отрисовки.
15. **M-16 Отзывчивая ширина** — `html,body{min-width:600px}` (`styles.css:21`) и
    фиксированные три колонки: в узком окне карта страдает первой.
16. **M-17 Карта в CI** — сейчас в CI нет ни одного теста карты
    (`.github/workflows/revival-baseline.yml` запускает только
    `tools/verify-baseline.ps1`; `tests/map-access.mjs` самоотключается без
    Playwright, а map-смоуки ATTACH-ONLY). Плюс два существующих смоука
    (`tools/smoke-map-product.mjs`, `tools/smoke-map-dock-product.mjs`) мутируют
    `window.state` напрямую в обход Core — при работе по M-03 их надо переписать.

## Решения, нужные от пользователя

| Вопрос | Варианты |
|--------|----------|
| M-02 drag внутри проекта | сохранять позицию (Core + `applyTaskPlacement`) **или** отключить и объяснять |
| M-05 материалы «без контекста» | считать на карте отдельной группой **или** не показывать |
| M-01b `layoutMode` | открыть режим «вручную» в интерфейсе **или** убрать из семантики |

## Проверка (как убедиться, что стало лучше)

- `tests/map-hit-hierarchy.mjs` — focused регрессия попадания и иерархии: орб
  внутри проекта берёт задачу, пустая территория проекта берёт проект, орбы группы
  берут задачу, пустота не берёт ничего, реальный клик открывает задачу в
  инспекторе (5 проверок).
- `output/map-prep-probe.mjs` — числовая проба геометрии (пересечения территорий,
  вложенность, ответ «что под курсором»); использована для D1-D8.
- `tests/map-access.mjs` — доступность и упаковка: фокус канваса, зона попадания,
  клавиатура, Escape, `fitGroup`.
- `.agents/skills/atlas-visual-verification` — 24 скриншота и замеры контраста,
  кегля и колонок сетки в двух темах и двух вьюпортах.
- `tools/smoke-map-product.mjs`, `tools/smoke-map-dock-product.mjs` — визуальный
  смоук в реальном браузере (ATTACH-ONLY, запускается вручную).
