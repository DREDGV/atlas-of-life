# Браузерная smoke-проверка

Проверка выполняется в отдельном браузерном профиле. Не импортируйте тестовый набор в профиль с личными данными.

## Подготовка

1. Запустить приложение из корня проекта:

   ```powershell
   python -m http.server 8000 --bind 127.0.0.1
   ```

2. Открыть `http://127.0.0.1:8000` в чистом профиле браузера.
3. Открыть консоль разработчика и оставить её видимой до конца проверки.

## Основной сценарий

1. Карта открывается, Canvas отображает демо-домены, проекты и задачи.
2. В фильтрах отсутствует `#undefined`.
3. Переключение `Карта` → `Сегодня` показывает задачи на сегодня.
4. В быстром вводе создать:

   ```text
   Smoke-проверка #автотест ~15м p2
   ```

5. Новая задача появляется в Today, тег `#автотест` — в фильтрах, оценка — `~15м`.
6. Вернуться на карту; интерфейс продолжает реагировать на pan и zoom.
7. В консоли нет ошибок и предупреждений приложения.

## Проверка старых данных

1. Через `Импорт` выбрать `tests/fixtures/legacy-state-v1.json`.
2. После импорта виден домен `Тестовый домен` и тег `#проект`.
3. Тег `#undefined` отсутствует.
4. Нажать `Экспорт` и открыть полученный `atlas_export.json`.
5. Убедиться, что:
   - `schema` равна текущей версии (`4` после добавления журнала операций);
   - в файле один домен, один проект и одна задача;
   - `projects[0].tags` равен `["проект"]`;
   - `tasks[0].tags` равен `[]`.

## Проверка Inbox MVP

1. Нажать `N` вне поля ввода — открывается «Быстрый захват», создание домена не запускается.
2. Ввести две непустые строки и сохранить через `Ctrl+Enter`.
3. В списке появляются две отдельные записи, счётчик в шапке увеличивается на 2.
4. Удалить запись и нажать `Отменить` — запись и счётчик восстанавливаются.
5. Нажать `В задачу` — запись исчезает из Inbox и создаётся backlog-задача в активном или первом домене.
6. Перезагрузить страницу — Inbox и созданная задача сохраняются.
7. Экспорт содержит актуальную схему, массив `inbox` и созданную задачу.

3 августа 2026 года весь сценарий Inbox пройден в отдельной Chromium-сессии; консоль осталась без ошибок и предупреждений.

## Проверка Atlas Core

1. Через быстрый ввод создать задачу — в экспорте появляется операция `task.create`.
2. Создать Inbox-запись — появляется операция `inbox.capture`.
3. У операций один непустой `deviceId`, уникальные `id` и `syncStatus: "pending"`.
4. Перезагрузить страницу и повторить экспорт.
5. Убедиться, что `schema` равна `4`, а операции сохранились без изменений.

3 августа 2026 года сценарий пройден: две операции сохранились после перезагрузки, экспорт корректен, консоль — 0 ошибок и 0 предупреждений.

Дополнительно проверена полная миграция тестового файла schema 1 → 4: домены, проекты, задачи и теги сохранены, `operationLog` корректно создан пустым, консоль осталась чистой.

## Проверка переноса задачи и Undo

1. Перетащить задачу из одного проекта в другой и подтвердить `Привязать`.
2. Убедиться, что задача появилась в целевом проекте, а в журнале создана операция `task.move`.
3. Проверить, что `payload.before.projectId` содержит исходный проект, а `payload.after.projectId` — целевой.
4. Нажать `Ctrl+Z`.
5. Убедиться, что задача вернулась в исходный проект, а журнал получил `task.move.undo` со ссылкой `sourceOperationId` на отменённый перенос.
6. Начать отвязку задачи и нажать `Отмена` — узел сразу возвращается на исходную позицию.
7. В консоли нет ошибок и предупреждений.

3 августа 2026 года сценарий пройден в отдельной Chromium-сессии: перенос `p1 → p2` сохранён как `task.move`, `Ctrl+Z` восстановил `p1` и добавил `task.move.undo`; консоль — 0 ошибок, 0 предупреждений.
