# Skill: atlas-work-ledger

Реестр работ — единственный список задач проекта: `docs/WORK_LEDGER.md`.
Отдельный разбор по карте — `docs/MAP_IMPROVEMENTS.md`.

## Зачем

Пользователь добавляет работу во время работы. Без реестра новая задача либо
теряется, либо молча вытесняет начатую. Реестр делает это видимым: у каждой
задачи есть номер, приоритет и статус, а не «помню/не помню».

## Алгоритм

1. **Начало работы.** Открыть `docs/WORK_LEDGER.md`. Взять верхнюю задачу своего
   приоритета из раздела «сейчас в работе» либо добавить туда новую строку.
2. **Новая задача во время работы** (от пользователя, из наблюдения, из кода):
   - не бросать начатое молча;
   - добавить строку в нужный раздел с номером и приоритетом (`P0…P3`);
   - если задача меняет текущее направление — сказать об этом пользователю одной
     фразой и продолжить по его выбору.
3. **Статус.** Перед правкой кода поставить `◐`, сразу после проверок — `✅`.
   В отчёте пользователю держать короткий блок «сделано / в работе / дальше».
4. **Завершение куска.** Отметить в реестре, обновить `docs/ROADMAP_REVIVAL.md`,
   если это этап дорожной карты, затем commit + push только относящихся путей.
5. **Вопросы, которые нельзя решить самому** (продуктовый выбор): вынести в раздел
   «Ждут решения пользователя» и не начинать их, пока нет ответа.

## Правила

- Реестр не заменяет roadmap: `docs/ROADMAP_REVIVAL.md` — про этапы версий,
  реестр — про конкретные задачи и их статус.
- Новый пункт без номера и приоритета — не пункт.
- Не удалять выполненные строки: переносить в журнал изменений, чтобы было видно,
  что именно сделано и когда.
- Реестр — документ, а не отчётность ради отчётности: одна строка на задачу,
  подробности — в профильном документе.

## Типичный промт

> Продолжай по реестру. Отметь сделанное, возьми следующий пункт, обнови реестр и отчитайся.
